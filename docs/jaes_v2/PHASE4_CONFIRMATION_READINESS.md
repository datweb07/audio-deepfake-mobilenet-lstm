The [ASVspoof 5 paper](https://arxiv.org/html/2502.08857v1) describes paired codec conditions for a subset and withholds attack-generation protocols for direct public use. Codec pairing therefore must not be relabelled as verified cross-generator content matching. The [34data secondary release](https://huggingface.co/datasets/34data/asvspoof5-bonafide-provenance) explicitly reassigns some neural-codec bona-fide reconstructions to synthetic. This changes task-label conventions; it is not a drop-in official-label confirmation corpus. No audio/protocol archive or evaluation labels from these candidates were acquired in Phase 4.

The metadata-only draft/checker records primary hypothesis, estimand, matching rule, conditions, inherited-threshold policy, correction family and success/failure interpretation. Missing: exact independent corpus/revision/IDs, source/overlap evidence, artifact lock for the new study and a justified precision plan. It refuses development-ID reuse and insufficient group support. A complete draft would still require provenance review; it does not enable prediction or authenticate evidence automatically.

Primary hypothesis must be identified as selected using development, not retroactively prespecified before Phase 3. Candidate A estimand is an equal-independent-source-group mean of matched-system differences in AB−BA FAKE misses. One declared primary factor contrast, practical-effect threshold and confidence procedure must be fixed before opening labels. Secondary inferential tests need a declared Holm family. Calibration must be separate; inherited .82/.12 may instead remain a declared artifact-transfer policy.

Machine draft/readiness: phase4_source_matching/confirmation_draft.json and confirmation_readiness.json. Exact IDs/hashes remain absent on purpose; there is no confirmatory CLI. Required next inputs are metadata/provenance and access that make A feasible, or an explicitly narrower B protocol. No organization was contacted and no account-sharing consent was accepted automatically.
