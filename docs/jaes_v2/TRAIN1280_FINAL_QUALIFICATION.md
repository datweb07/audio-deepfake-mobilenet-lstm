## Prospective estimand and design

If the supervisor requires an extension, prioritize one fixed-epoch comparison using 9207, the already specified candidate seed in the prior readiness report. Compare Channel-minus-ERM at 640 and 1,280 for the same independently initialized seed block and unchanged development A/B. Each new arm would use 21 passes over its cohort, 16 sources per optimizer update, 1 warm-up and 20 partial fine-tuning epochs, unchanged epoch-indexed learning rate, same augmentation bank, optimizer and checkpoint rule, and the same per-epoch validation schedule. At 1,280 that implies 80 updates per epoch and 1,680 updates per arm. The estimand is sensitivity to the nested source pool under equal passes and the same epoch-based policy. Additional updates and compute are part of that estimand. It cannot isolate size at fixed compute. Keeping 840 updates would end partway through epoch 11 and double the warm-up update count if warm-up stays one epoch. That design needs a step-defined stage and selection schedule for a distinct fixed-compute estimand. Neither contrast provides independent confirmation on the already used development cohort or stability over seeds.

Freeze the candidate and specify stress AUC, classwise errors, A05/A06, B clean guard, and signed order contrasts before any run. Report the two within-size effects and their difference with matched development speaker resampling. A reversal or null effect is a valid result. The previously opened official evaluation remains outside selection and reporting for this size diagnostic.

## Technical gate and runtime

Both bounded negative probes invoked the existing config constructor with the real candidate path and 840 or 1,680 updates. Both raised `Only locked allowed train/development manifests`. The current loader accepts only the sealed medium or foundation paths and enforces their associated development manifest. The registry and launcher admit only registered medium experiment IDs, and the prospective engine enforces the medium execution role. An isolated candidate profile cannot be registered by adding a JSON file to this release. It needs a separately reviewed adapter and fingerprint/admission contract. The released engine and its source checks remain authoritative for the existing evidence.

No model initialization, forward or gradient, optimizer step, checkpoint write/restore, exact resume, validation parity, export, seal or resource-stop test was executed on 1,280 because admission stopped before those stages. The previously validated 640 qualification and existing regression tests do not certify 1,280. There are no valid train, smoke, resume or compare commands for this profile. For a future profile, run an isolated continuous versus interrupted fixture including the warm-up boundary, actual augmentation, finite/nonzero gradients, optimizer state, LR, counters, validation, export, seal and simulated resource stops before seeking approval.
